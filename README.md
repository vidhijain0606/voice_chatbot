# Voice-Enabled Chatbot

A voice-enabled chatbot combining **browser-based Speech Recognition** (Web
Speech API) with a **Deep Learning intent-classification model** (Keras
feedforward neural network) trained on a custom intents dataset.

**Live demo (deployed on GitHub Pages, 100% free, no backend):** `web/`
folder — see [Deployment](#deployment) below for the link once published.

## How it works
1. Click **🎤 Speak** — your browser's Web Speech API transcribes your voice to text (client-side).
2. The recognized text is run through a tiny hand-written neural-network forward pass, entirely in the browser (JavaScript), using the exact weights of the Keras model trained in Python.
3. A response for the predicted intent is displayed, alongside the recognized transcript and the model's confidence.
4. A manual text box is provided as a fallback for browsers without Web Speech support (e.g. Firefox).

Everything — speech recognition and model inference — runs **client-side in
the browser**. There is no server, no API key, and no hosting cost: the
whole app is static HTML/CSS/JS that can be served from any static host
(GitHub Pages, Netlify, Vercel, etc.).

## Project structure
```
data/intents.json        # training dataset (tags, patterns, responses)
chatbot_model.py          # preprocessing (tokenize/bag-of-words) + Keras model architecture
train.py                  # trains the model, writes model/*.h5 + words/classes json+pkl
export_web_model.py       # exports trained weights as JSON for the browser (no TF.js needed)
model/                    # trained model artifacts (generated)
web/                      # the deployed static site
  index.html
  style.css
  app.js                  # Web Speech API + hand-written forward pass (mirrors chatbot_model.py)
  intents.json            # copy of data/intents.json (for responses)
  model/                  # weights.json, words.json, classes.json (generated by export_web_model.py)
app.py                    # OPTIONAL: local-only Gradio demo (Python backend) — not deployed,
                           # since Gradio/Docker Spaces on Hugging Face now require a paid plan.
                           # Kept for local testing / as an alternate reference implementation.
report.md                 # lab report (dataset, architecture, methodology, results)
```

## Regenerating the model
```bash
pip install -r requirements.txt
python train.py              # trains model/chatbot_model.h5 (Keras)
python export_web_model.py   # exports web/model/weights.json + words.json/classes.json + web/intents.json
```

## Run the static site locally
No build step or server framework needed — any static file server works:
```bash
cd web
python -m http.server 8080
# open http://127.0.0.1:8080
```

## Deployment (GitHub Pages — free)
1. Push this repo to GitHub (public or private both work for Pages on a public repo; Pages itself is free for public repos).
2. In the repo's **Settings → Pages**, set:
   - Source: "Deploy from a branch"
   - Branch: `master` (or `main`), folder: `/web`
3. GitHub Pages will publish the site at `https://<username>.github.io/<repo-name>/`.
4. Open the link in Chrome or Edge, allow microphone access, and test the 🎤 Speak button.

## Why not Hugging Face Spaces / Gradio?
Hugging Face Spaces now requires a paid plan to run Gradio or Docker Spaces
(free tier is limited to Static Spaces, which can't run a Python backend).
To keep this project fully free, the app was re-architected to run
entirely client-side (model weights exported to JSON, inference
hand-written in JavaScript) instead of relying on a hosted Python backend.
The original Gradio app (`app.py`) is kept in the repo as a local-only
reference/demo.
