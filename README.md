# VANI — Voice-Enabled Chatbot

**VANI** (from the Sanskrit/Hindi word for "voice") is a voice-enabled
chatbot combining **Azure AI Speech** (speech-to-text) with a **Deep
Learning intent-classification model** (Keras feedforward neural network)
trained on **Azure Machine Learning**, deployed on **Azure Static Web
Apps**.

**Author:** Vidhi Prashant Jain (23BAI0063)
**Live demo:** https://lively-smoke-01c7d2900.3.azurestaticapps.net

## How it works
1. Press the mic button in the input dock — the browser fetches a short-lived token from `/api/get-speech-token` (an Azure Function) and uses the Azure Speech SDK for JavaScript to transcribe your voice to text, showing a live interim caption in the status log while you talk (press it again to cancel).
2. The recognized text (or typed text) first passes through a small **smart-answers layer** (see below) that handles live weather, time, date, and quick math directly; anything else is run through a tiny hand-written neural-network forward pass, entirely in the browser (JavaScript), using the exact weights of the Keras model trained on Azure ML.
3. Weather and math replies render as **telemetry cards** (temperature/condition/wind, or expression → result); everything else renders as plain text.
4. A manual text box is provided as a fallback (also useful if microphone access isn't available or Speech quota is exhausted), plus quick-suggestion chips (weather / time / quick math / joke / help) to try things without typing.

Intent classification runs **client-side in the browser** — no server needed
for that part, and it's instant/free. The only server-side piece is the
Azure Function that mints a short-lived Speech token so the Speech
resource's secret key never reaches client code.

### Dashboard UI
The app is a full dashboard rather than a single chat card:
- **Sidebar** — a collapsible history of previous sessions, grouped into
  Today / Yesterday / Last 7 Days / Older, persisted in the browser's
  `localStorage` (no backend). "New session" archives the current
  conversation and starts fresh; clicking a past session reloads it.
- **Header actions** — Export transcript (downloads the active
  conversation as a local `.txt` file, generated client-side), Clear
  session (wipes the active conversation without archiving it), and a
  Settings popover for the microphone and recognition language.
- **Settings are real, not decorative** — the microphone dropdown lists
  actual input devices via `navigator.mediaDevices.enumerateDevices()`
  and is passed to `SpeechSDK.AudioConfig.fromMicrophoneInput(deviceId)`;
  the language dropdown (English US/UK, Hindi) sets
  `speechConfig.speechRecognitionLanguage` for the next recognition.

### Smart answers (weather, time, date, math)
Before falling back to the trained intent classifier, `web/app.js` checks
the message against a small ordered list of rule-based handlers:
- **Weather** — via [Open-Meteo](https://open-meteo.com) (free, no API key,
  called directly from the browser). Uses your device location (with
  permission) or a named city, e.g. "weather in Chennai".
- **Time** / **Date** — `Date` formatted locally in the browser.
- **Quick math** — simple arithmetic expressions (`+ - * / ()`), evaluated
  with a small hand-written parser (no `eval`).

These are plain deterministic JS, not part of the trained model — the NN
only ever selects from a fixed list of canned responses per intent, which
can't express live/computed answers like the current temperature or time.
No new Azure resources or secrets were needed for this: Open-Meteo and the
browser's Geolocation API are both keyless and client-side only.

## Project structure
```
data/intents.json        # training dataset (tags, patterns, responses)
chatbot_model.py          # preprocessing (tokenize/bag-of-words) + Keras model architecture
train.py                  # trains the model, writes model/*.h5 + words/classes json+pkl
export_web_model.py       # exports trained weights as JSON for the browser (no TF.js needed)
model/                    # trained model artifacts (generated)
web/                      # the deployed static site
  index.html
  style.css
  app.js                  # Azure Speech SDK + hand-written forward pass (mirrors chatbot_model.py)
  lib/speech-sdk.js        # vendored Azure Cognitive Services Speech SDK for JS
  staticwebapp.config.json # Azure Static Web Apps routing config
  intents.json             # copy of data/intents.json (for responses)
  model/                   # weights.json, words.json, classes.json (generated by export_web_model.py)
api/get-speech-token/      # Azure Function: exchanges the Speech resource key for a short-lived token
azureml/                   # Azure ML environment/job specs documenting the training setup
app.py                     # OPTIONAL: local-only Gradio demo (Python backend) — not deployed,
                            # since Gradio/Docker Spaces on Hugging Face require a paid plan.
                            # Kept for local testing / as an alternate reference implementation.
report.md                  # lab report (dataset, architecture, methodology, results)
AZURE_SETUP.md             # step-by-step Azure Portal setup guide used to deploy this project
```

## Regenerating the model
```bash
pip install -r requirements.txt
python train.py              # trains model/chatbot_model.h5 (Keras)
python export_web_model.py   # exports web/model/weights.json + words.json/classes.json + web/intents.json
```
In this project, `train.py` and `export_web_model.py` were run on an Azure
Machine Learning Compute Instance (see `AZURE_SETUP.md` Phase 3), then the
regenerated artifacts were pushed back to this repo.

## Run the static site locally
No build step or server framework needed — any static file server works
(note: the `/api/get-speech-token` route won't work locally without the
Azure Functions Core Tools + a local `SPEECH_KEY`/`SPEECH_REGION`; the text
input still works fully offline):
```bash
cd web
python -m http.server 8080
# open http://127.0.0.1:8080
```

## Deployment (Azure)
Full step-by-step instructions are in [`AZURE_SETUP.md`](AZURE_SETUP.md).
Summary:
1. **Azure AI Speech** resource (F0 free tier) — powers speech-to-text.
2. **Azure Machine Learning** workspace + Compute Instance — runs `train.py` / `export_web_model.py`.
3. **Azure Static Web Apps** (Free tier) — hosts `web/` (static site) + `api/` (the token-minting Azure Function), auto-deployed via a GitHub Actions workflow on every push to `main`. The Speech resource's key is stored as a Static Web App **Environment Variable** (`SPEECH_KEY`, `SPEECH_REGION`) — never committed to source control.

## Why Azure, and why client-side inference?
The project originally targeted Hugging Face Spaces, but Spaces requires a
paid plan to run Gradio/Docker apps (the free tier is Static-only). It was
re-architected to run intent classification entirely client-side (model
weights exported to JSON, inference hand-written in JavaScript — no
TensorFlow.js runtime needed), then migrated end-to-end onto Azure so that
speech recognition, model training, and hosting all use the same cloud
platform. The original Gradio app (`app.py`) is kept in the repo as a
local-only reference/demo.
